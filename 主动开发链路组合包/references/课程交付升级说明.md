# 课程交付升级说明

这份文档只服务课程交付口径，不进入 runtime 契约。

## 一、飞书的定位

统一口径：

- 飞书是课堂标准沙盘，不是企业唯一答案
- 企业已有 CRM、ERP、Excel、Google Sheet、WPS、企业微信表格，都可以是数据容器
- 课堂先跑通标准数据契约和闭环，不要求所有人现场接企业系统
- 标准 Base 只作为参考模板，不作为企业落地强制前置
- 用户已有表头优先沿用；没有可用表格时，龙虾再按企业产品、市场和流程新建够用表

## 二、课堂主线

新的主线不是“会不会搭飞书”，而是：

- 有没有跑通标准字段
- 有没有形成可复核的主动开发闭环
- 有没有开始沉淀客户开发数据资产
- 有没有把确认过的新字段、客户分级、搜索数据源、近期客户信号、市场信号、背调规则、开发信风格、禁用表达和行业习惯沉淀成可复用规则

固定提醒：

- Skill 是标准化能力，不是固定表格模板。
- 规则沉淀前必须追问：`是否更新到对应 Skill 以便下次自动复用`。
- 真实写入 Skill 必须得到用户授权。

## 三、建议教学顺序

教学顺序建议调整为：

1. 先用客户背调建立信任：它是整套链路里的核心判断层
2. 再讲主动搜索的边界和证据分级
3. 再讲线索整理和质量门槛
4. 最后讲复核型开发信工作台和数据回流：开发信调用背调信号，不自行编造近期动态

## 四、组合包落地口径

组合包不要讲成“越完整越高级”。它在课程里的作用是让主代理像项目经理一样减少切换、安排 4 个子代理、统一主表和失败收口。

真实落地优先按节点推进：

1. 先跑 1 个已知客户的背调，确认判断质量
2. 再跑 3-5 条候选客户的搜索和整理，确认证据和质量门槛
3. 最后只把通过门槛的对象推进到开发信草稿

如果证据不足，正确动作是 hold、补证据或人工复核，不是为了完成组合包而强行跑满四阶段。

## 五、课前 48 小时预检

建议收集：

- 主营产品
- 目标国家/市场
- 是否已有 CRM
- 使用 Gmail / Outlook / 企业邮箱
- 是否愿意用飞书
- 是否有技术同事
- 一个已知客户官网

## 六、课程与课后承接

### 线下课

- 跑通标准闭环
- 完成第一个真实案例
- 看懂数据契约和容器方案

### 1 个月复盘

- 解决部署和 Skill 卡点
- 解决表格 / 飞书 / 字段映射问题

### 年度会员

- 持续更新 Skill、SOP、工具和接入案例

### 高阶定制

- CRM / ERP / 邮箱 / 私有系统接入

## 七、仓库与飞书分工

- GitHub 仓库只放执行能力、脚本、样例、数据契约和 handoff contract。
- 飞书知识库负责教学解释、演示、复制词、截图说明和价值传递。
- Lesson 正文、截图说明和增强权益价值阐述不要写入仓库；仓库侧只保留链接和执行契约。
