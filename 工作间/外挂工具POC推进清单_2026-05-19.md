> 归档标记：本文件只作为 2026-05-19 当轮 POC 推进证据保留；当前推进顺序、状态和下一动作以 `精选外部Skill候选验证台账.md` 为准。

## 当前只推进六条

后续排期见：`外挂工具后续推进路线图_2026-05-19.md`

1. Codex Subagents 使用模板与本地作战台派工边界
2. Multica 本地作战台 agent team 面板参考 POC
3. Flowboard 到 TikTok 视频营销链路的节点流拆解
4. LLM Wiki 本地企业知识库验证
5. Agent 功能上架检查清单
6. HTML 输出链验证：`html-anything / wechat-publish-template / snapdom`

暂缓：Hermes Web UI 旁路控制台。它有价值，但需要等前面 POC 收口，避免扰动 Hermes / OpenClaw 稳态。

## 推荐推进顺序

1. 先做 `Codex Subagents 使用模板`：立刻能提升 Codex 长任务质量。
2. 同步评估 `Multica`：只看派工、进度、技能沉淀和运行时注册，不碰生产运行栈。
3. 再把 `Flowboard` 拆成 TikTok 视频营销节点流，反哺课程侧 P1 方向。
4. 继续做 `LLM Wiki 本地企业知识库 POC`：贴近本地作战台核心命题。
5. 同步做 `Agent 上架检查清单`：后续所有功能先过 gate。
6. 再做 `HTML 输出链 POC`：提升品牌工作间成品效率。

## 决策出口

每个 POC 完成后，只允许给四种结论：

- `继续二阶段`
- `只保留参考`
- `暂缓`
- `放弃`

不得写成“已经适合作战台上线”，除非完成最小样例、边界说明、失败模式和用户侧验收。
