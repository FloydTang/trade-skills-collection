# 精选外部Skill晋升通道与论坛同步流程 2026-05-19

> 方向标记：本文件是精选外部Skill从候选、POC、人工审核到工具库、课程化、作战台和论坛反馈回流的稳定 SOP。

## 一句话

精选外部Skill 不从论坛进工具库，也不从 GitHub 列表直接进作战台。

正确方向是：先在本地工作间验证和提纯，再落到工具库；进了工具库的内容，先交给课程工作间课程化，再进入课程库、作战台、飞书知识库和论坛推广。

稳定通路是：

```text
工具工作间候选
-> 本地 POC / 最小样例验证
-> 人工审核和脱敏
-> 半斤九两工具库落库
-> 课程工作间课程化
-> 半斤九两课程库
-> 作战台同步 / 飞书知识库同步
-> 论坛推广、讨论和反馈回流
```

## 现有作战台通路

当前作战台已经有几条可以承接“课程化成品分发与反馈回流”的能力：

- `#/forum`：年度会员论坛，支持看帖、提问、回答、Skill 分享、工具推荐和待审核发布。
- `scope=forum` 学习链接：年度会员可给智能体，让智能体读论坛、整理帖子和提交草稿。
- Agent API：智能体可读取论坛 feed，也可提交帖子 / 回答草稿；提交后进入主人待审核区，不自动公开。
- `forum_skill_requests`：用于记录用户对课程化成品、论坛推广帖或精选内容的反馈请求；它只能进入工作间评估，不能直接写入工具库。
- `/api/library`：弹药库只展示 `libraryReady` 资产；当前门槛是已审核、来源存在、正文长度足够，且不处于 `needs_review`。
- `assetKind=skill`：只有绑定明确开源 Skill 骨架、安装入口或 `skill.md` 的资产，才在作战台里标为 Skill；否则只能叫描述词或工具参考。

## 晋升分层

| 层级 | 名称 | 存放位置 | 进入条件 | 出口 |
| --- | --- | --- | --- | --- |
| L0 | 发现候选 | `开源工具总表.md`、`路线映射.md` | 有明确来源和可能业务用途 | 进入当前台账或只保留参考 |
| L1 | POC 候选 | `精选外部Skill候选验证台账.md` | 能对应外贸、内容、知识库、设计或工程维护场景 | 做最小样例 |
| L2 | 本地验证中 | `工作间/孵化中/` 或内部维护文档 | 能跑出可复查样例，有失败边界 | 继续迭代或进入人工审核 |
| L3 | 工具库预发布 | `半斤九两工具库/精选外挂开源Skill`，若是外贸业务增强则转入 `半斤九两工具库/外贸业务主干Skill` | 人工审核通过，有安装/使用/边界/验证记录 | 进入同步清单，交给课程工作间 |
| L4 | 课程化处理 | 课程工作间 | 能讲清课程场景、用户动作、作业和权益边界 | 进入课程库或退回工具工作间补证据 |
| L5 | 课程库 / 飞书同步 | 半斤九两课程库、飞书知识库 | 课程正文和增强入口更新完成 | 作战台可同步 |
| L6 | 作战台发布与论坛推广 | 作战台弹药库、授权学习链接、论坛 | `approved`、有来源、可复制或可安装、权限正确 | 用户可见或按权益锁定，反馈回工作间 |

## 每日节奏

每日可以让 AI 工具自动做这些事：

1. 读取论坛 `hot / latest / Skill 分享 / 工具推荐 / 龙虾日记`。
2. 从每条帖子里抽取：名称、用处、给外贸企业的帮助、验证证据、风险边界。
3. 把明显不适合公开的内容打回：含客户隐私、API Key、报价细节、未脱敏成交数据。
4. 对值得推进的反馈生成候选卡，只进入工作间评估，不直接落工具库。
5. 给运营者输出每日摘要：工具库成品推广效果、用户反馈、待验证新需求、可回帖内容。

每日更新的目标是“发现和整理”，不是“发布和落库”。

## 每周节奏

每周做一次人工晋升：

1. 从 POC 清单、候选清单和论坛反馈里选 1-3 个最高价值方向。
2. 补齐本地最小样例、失败边界和来源证明。
3. 判断资产类型：
   - 有开源骨架、安装入口或 `skill.md`：可以标成 Skill。
   - 只有一段执行词或帖子摘要：只能标成描述词或工具参考。
4. 通过后落到对应工具库成品层：精选外部Skill进入 `半斤九两工具库/精选外挂开源Skill`；外贸业务增强进入 `半斤九两工具库/外贸业务主干Skill`，并更新对应云端同步清单。
5. 交给课程工作间判断课程章节、作业、案例、权益层和飞书增强入口。
6. 课程库和飞书知识库更新后，再生成或更新作战台同步稿；如需进入线上作战台，再写入 D1 发布缓存，保证 `content_review_status='approved'`、来源字段完整、正文足够长。

## 工具库落库要求

每个外挂精选资产进入工具库前，至少要有：

- `README.md`：它是什么、解决什么业务问题、适合谁用。
- 来源与许可证：GitHub / 官方文档 / 已装本地 Skill 来源。
- 最小样例：输入、执行方式、输出结果、失败样例或误报说明。
- 安全边界：隐私、账号、API Key、数据出境、误判风险。
- 课程化建议：适合哪一课、哪一个作业、哪一个用户动作；是否可复制、可收藏、可授权给智能体。
- 课程回流判断：是否需要更新课程正文、飞书知识库或论坛置顶帖。

没有这些材料，不进入工具库成品层，只能留在工作间继续验证。

## 论坛与工具库边界

论坛负责推广、讨论、答疑、反馈、投票和沉淀需求。

工具库负责保存已经提纯、验证、可追溯、可被课程工作间读取的成品或准成品。

所以不能让论坛帖子自动写入工具库；论坛里再热的反馈，也只能回到工作间排队验证。反过来，课程化后的工具库成品可以同步到论坛做“本周新增弹药”说明，帮助会员知道怎么用。

## 推荐的首批晋升方向

| 方向 | 当前状态 | 建议动作 |
| --- | --- | --- |
| `changedetection.io` / 竞品监控 | 已有最小样例和作战台价值 | 优先补齐工具库落库材料，通过后交给课程工作间写成竞品监控课程卡 |
| `llm_wiki` / 本地企业知识库 | 候选价值高 | 先做本地 POC，不急着进课程库、作战台或论坛 |
| `AfterShip/email-verifier` + `mailchecker` | 与客户开发强相关 | 做邮箱质量最小样例，重点验证误判 |
| `sherlock` / `maigret` | 已作为社媒初筛候选 | 先验证误报，通过后由课程工作间整理方法和边界 |
| `html-anything` / `wechat-publish-template` / `snapdom` | 内容输出链候选 | 先做内容营销样例，通过后再进工具库和课程工作间 |
| `12-factor-agents` | 方法层价值明确 | 转成 Agent 上架检查 gate，不作为用户运行时 Skill |

## 一条硬规则

课程工作间读取工具库，作战台读取课程化结果，论坛推广课程化结果。工具库只吃“通过验证的成品”，论坛只做分发、讨论和反馈回流。
