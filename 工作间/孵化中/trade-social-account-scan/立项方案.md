# trade-social-account-scan 立项方案

## 基本信息

- Skill 名称：社媒账号初步调研 Skill
- 建议英文名：`trade-social-account-scan`
- 所属业务节点：主动开发前的公开来源补查 / 市场调研轻量入口
- 负责人：Codex + Floyd
- 当前状态：可演示前验证中

## 业务问题

- 这个 Skill 要解决的具体问题是什么：
  客户或竞品官网之外，社媒上可能有产品、活动、渠道、招聘和展会线索，但人工逐个平台搜索耗时，也容易误判账号身份。
- 当前人工是怎么做的：
  人工用公司名、品牌名和产品关键词分别在 Google、LinkedIn、Instagram、Facebook、TikTok、YouTube 等平台搜索，再凭经验判断哪个账号可能相关。
- 为什么值得被做成 Skill：
  这一步能为客户背调和开发信提供更接近市场一线的公开信号，但必须把“候选账号”和“官方确认”分开。

## 成功标准

- 最小成功结果是什么：
  输入公司名、官网或市场信息后，输出平台搜索策略、账号候选、活跃度初判、公开业务线索和是否值得进入深度分析。
- 用户拿到结果后，能直接做什么下一步动作：
  把可信候选账号交给客户背调节点继续核验，或决定暂不投入深度社媒分析。
- 什么情况下算“做出来了但还不能交付”：
  能列出很多账号，但无法解释账号相关性、误报风险和人工复核路径。

## 输入

- 最小输入：
  公司名、官网或国家市场、产品关键词。
- 可选输入：
  已知社媒链接、品牌别名、负责人姓名、目标平台、禁搜平台、语言市场。
- 输入示例：
  见 `examples/minimal-input.json`。

## 输出

- 核心输出：
  推荐搜索平台、平台关键词、账号候选列表、相关性理由、活跃度初判、公开业务线索、复核建议、是否进入 TikTok / 内容品牌深度专项。
- 输出格式：Markdown / JSON
- 输出示例：
  等公开样例跑通后补入 `examples/`。

## 核心规则与边界

- 必须遵守的业务规则：
  只使用公开信息；必须把候选账号、疑似官方账号、已确认官方账号分开标注。
- 哪些信息只能写成推断：
  账号归属、运营意图、采购需求、渠道策略、内容团队能力。
- 哪些情况必须提示人工复核：
  公司名是常见词、账号使用缩写、多个同名品牌、个人账号疑似关联、平台账号长期未更新。
- 明确不做什么：
  不下载或搬运对方内容；不复刻对方账号；不承诺找到全部平台账号；不把 Sherlock / Maigret 输出直接当官方账号确认。

## 依赖与实现方式

- 需要的脚本 / 工具 / API：
  首版默认公开网页搜索；Sherlock / Maigret 只作为候选增强工具观察。
- 是否需要联网：
  需要。
- 是面向 Codex、本地脚本，还是 OpenClaw / 龙虾优先：
  首版优先面向 Codex / OpenClaw 可读执行词。
- 是否需要 `for-openclaw/` 变体：
  样例验证稳定后再决定。

## 课程与内容映射

- 对应课程：
  作战台 V1.5 `社媒账号初步调研执行词`、外贸主动开发课 Lesson 04、内容营销 Skill 的前置筛查信号。
- 可讲成什么案例：
  如何把社媒公开信息从“随手看看”变成“有证据、有边界、有下一步”的初筛。
- 可衍生什么内容选题：
  怎么判断客户有没有社媒线索、如何避免把假账号当官方账号、什么时候值得进入 TikTok 深度分析。

## 内容营销分流 2026-05-21

- TikTok / YouTube / Instagram 的视频内容拆解、选题库、脚本任务包和询盘承接，统一并入 `外贸业务主干Skill` 的内容营销 / TikTok 陪跑分支。
- 本 Skill 只负责发现公开社媒账号候选、标注不确定性、给出是否值得进入内容营销深度分析的建议。
- 边界不变：不下载竞品视频，不复刻账号，不承诺播放量，不做自动发布或投流。

## 验收方式

- 最小测试输入是什么：
  1 个客户公司、1 个竞品公司、1 个无明显社媒账号样例。
- 预期输出应包含哪些关键信息：
  搜索平台、关键词、候选账号、相关性理由、活跃度初判、业务线索、复核建议。
- 如何判断这个 Skill 已达到可演示：
  至少 3 类样例都能输出保守、可解释的账号候选和下一步建议。
- 如何判断这个 Skill 已达到可交付：
  至少 2 轮公开样例稳定通过，并写清 Sherlock / Maigret 是否接入、怎么接入、失败时如何解释。
