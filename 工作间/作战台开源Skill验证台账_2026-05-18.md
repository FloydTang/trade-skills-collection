## 第一批验证任务

### 1. Mail Group 最小样例

输入：

- 我司产品
- 目标市场
- 5-10 条客户名单
- 每条客户的行业、国家、来源、背调摘要或备注

输出必须包含：

- 分组名称
- 每组共同特征
- 每组首封邮件角度
- 每组英文标题候选
- 每组首封草稿
- 第一次跟进节奏
- 必须补充的背调信息

不做：

- 不自动发送邮件
- 不配置 SMTP
- 不承诺回复率
- 不把分组推断写成客户事实

### 2. 社媒账号初步调研最小样例

输入：

- 公司名
- 官网或国家市场
- 产品关键词
- 可选：已知社媒链接

输出必须包含：

- 推荐搜索平台
- 平台关键词
- 账号候选列表
- 活跃度初判
- 公开业务线索
- 可进入客户背调 / 开发信的线索
- 是否值得进入 TikTok / 内容品牌深度专项

不做：

- 不下载或搬运对方内容
- 不复刻对方账号
- 不把个人账号当公司官方账号
- 不承诺找到所有平台账号

### 3. Feishu KB 内部样例

输入：

- 课程源目录
- 目标飞书知识库入口
- 已有索引页或目录规则

输出必须包含：

- 课程源映射
- 入口页结构建议
- 权限边界
- 同步动作建议
- 回读验收点

不做：

- 不绕过飞书权限
- 不把公开仓库写成增强权益正文
- 不强制企业使用固定 Base 或固定表头

## 发布判断

可演示：

- 最小样例跑通。
- 输出能解释事实、证据和推断。
- 有明确人工复核点。
- 能被课程讲清楚“为什么这样拆”。

可交付：

- 至少 2 组样例稳定通过。
- README / SKILL / examples / references 至少齐备到当前合集收录标准。
- 如依赖开源工具，工具的安装、失败模式和许可证边界已经写清。
- 可以进入合集仓库，且不依赖用户额外初始化复杂服务。
