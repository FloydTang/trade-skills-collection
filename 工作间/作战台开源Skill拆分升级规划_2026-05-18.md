# 作战台开源 Skill 拆分升级规划

> 归档标记：本文件只作为 2026-05-18 当轮“作战台开源 Skill”拆分过程证据保留；当前工具 / 课程链路以 `外贸业务主干Skill云端同步清单.md`、`开源工具总表.md` 和 `路线映射.md` 为准。

更新日期：2026-05-19

## 背景

作战台 Session 提出后续单开新 Session 做开源 Skill 时，优先拆：

- `trade-lead-search`
- `trade-lead-screening`
- `trade-customer-intel`
- `trade-outreach-draft`
- `trade-mail-group`
- `trade-feishu-kb`
- `trade-social-account-scan`

本规划的判断是：这个拆法成立，但不应塞进作战台主界面。作战台主页面继续保持“作战包、弹药库、论坛、龙虾学习链接”的清爽口径；这些 Skill 放在工具工作间继续孵化、验证和发布。

## 当前结论

- 当前公开交付仍以 `trade-skills-collection` 合集仓库为主入口。
- 已经成熟的单节点继续沿用原仓库，不为了命名一致重复造仓库。
- 新增节点先进入需求池和验证台账，验证通过后再决定是否独立仓库、是否进合集仓库。
- 作战台里的 Mail Group 和社媒账号初步调研，当前先理解为“弹药库描述词 / 执行词已经露头”，下一步才是把它们升级成真正的 Skill。
- `trade-feishu-kb` 涉及权限、飞书结构和企业容器，不作为公开默认安装项，优先放在增强 / 内部 Skill 路线。

## 2026-05-19 当前进度同步

- 成品层已经收口到半斤九两工具库 `外贸业务主干Skill`；后续应先交给课程工作间课程化，再同步课程库、作战台和飞书知识库，而不是让作战台读取工具工作间的开发过程文档。
- 当前成品入口固定为 `README.md`、`OPENCLAW.md`、`当前推荐安装清单.md`。
- `主动开发链路组合包` 已从“设计中”推进到“可演示”，当前用于串联 `客户搜索skill -> 线索整理skill -> 客户背调skill -> 开发信skill`。
- 成品层已补齐组合包运行说明、容器口径、飞书沙盘边界、表头适配与规则沉淀提醒；不再把组合包理解成强制固定 Base 或强制总编排器。
- 新增的 `trade-mail-group` 已补齐本地可演示包，但仍需 OpenClaw / 真实业务样例复核；`trade-social-account-scan`、`trade-feishu-kb` 仍在可演示前验证中。它们都不进入当前公开默认安装清单。
- 新增的 `trade-market-pulse` 已从半斤九两工作台 `AI热点 / 每日内容同步` 机制拆出为外贸市场脉搏候选，当前只是设计中；它和 `竞品监控skill` 共享“持续观察”场景，但不替代已有页面变化监控。
- Obsidian 展现层当前路径为 `工具工作间/02_场景拆解/外贸业务主干Skill`；早期 `工具工作间/外贸skill` 路径不再作为当前展示位置。

## 推荐优先级

第一批先做：

1. `trade-mail-group`
2. `trade-social-account-scan`
3. 现有 `trade-outreach-email` 的 draft 口径优化

原因：

- 这两个新节点已经在作战台 V1.5 内容升级中出现。
- 它们能补齐主动开发中“分组触达”和“公开社媒初筛”两个真实动作。
- 两者都可以先做轻量 Skill，不需要重型 SaaS、CRM 或发信系统。

第二批再做：

1. `trade-feishu-kb`
2. `trade-lead-search` 的搜索源 / 联系方式补查增强
3. `trade-customer-intel` 的社媒证据增强
4. `trade-market-pulse` 的每日市场情报样例验证

当前执行顺序：

1. 先让 OpenClaw 复核 `trade-mail-group`，确认它能从 5-10 条客户名单输出可复核的分组、角度、标题、草稿和跟进节奏。
2. 再跑 `trade-social-account-scan`，先用公开网页搜索建立保守输出标准，再决定是否引入 Sherlock / Maigret 做候选账号发现辅助。
3. `trade-feishu-kb` 暂时只作为增强 / 内部 Skill 样例，不进入公开默认安装和作战台主页面。
4. `trade-market-pulse` 先跑课程模拟样例，验证来源桶、证据等级和业务动作建议，再决定是否接自动化调度。

当前存储标准：

- 新增方向的真实源都在 `工作间/孵化中/`。
- Obsidian 只镜像 README、立项方案和验收清单，不镜像 examples、scripts 或临时运行产物。
- 半斤九两工具库 `外贸skill` 只保留已可演示 / 可交付的成品，不收录这些未跑样例的新候选。

## 验证门槛

任何新 Skill 进入开发前，至少满足：

- 有最小输入和结构化输出。
- 至少 2 组样例：课程样例 + 真实公开样例。
- 能明确事实、证据、推断和人工复核项。
- 不暗示访问私有数据或未授权系统。
- 不自动发信、不自动发帖、不自动写入企业系统。
- 能讲成课程案例，也能被龙虾 / Codex 即插即用。

任何开源工具进入默认推荐前，至少满足：

- 仓库未归档，许可证和依赖边界清楚。
- 最小命令能跑通，或至少能用公开样例复现核心能力。
- 输出结果能被业务人员复核，而不是只给一堆技术日志。
- 失败时能解释失败原因，不把“不确定”包装成确定结果。

## 与作战台的边界

- 作战台：展示已筛选的作战包、描述词、Skill 入口和授权学习链接。
- 工具工作间：负责 Skill 拆分、验证、开源工具评估和长期规划。
- 飞书：负责课程正文、增强执行词、长期知识库和会员权益。
- GitHub 合集仓库：只收录已经达到可演示或可交付标准的节点。

一句话：作战台负责“拿来就用”，工具工作间负责“把能用的东西做扎实”。
