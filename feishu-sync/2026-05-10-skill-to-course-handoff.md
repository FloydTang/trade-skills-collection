# Skill to Course Handoff｜2026-05-10

## 1. 本次同步目标

把 `trade-skills-collection` 的外贸主动开发 Skill 口径升级为“标准化能力 + 企业表格适配 + 授权后规则沉淀”，并同步到飞书课程的描述词与 Lesson 文案。

## 2. GitHub 仓库权威口径

1. Skill 是标准化能力，覆盖搜索、线索整理、客户背调、开发信，不是固定表格模板。
2. 企业表格是企业个性化资产：用户已有表头优先沿用；没有可用表格时，由龙虾按企业产品、市场和流程新建够用表。
3. 标准 Base、课堂 Feishu Sandbox 和示例字段只作为参考映射，不是企业落地强制前置。
4. 当用户确认新字段、客户分级、背调规则、开发信风格、禁用表达或行业习惯时，龙虾必须追问：`是否更新到对应 Skill 以便下次自动复用`。真实写入必须得到用户授权。
5. GitHub 仓库只放执行能力、脚本、样例、标准数据契约、handoff contract 和表格适配契约；飞书知识库放教学、演示、复制词、截图说明和价值传递。

## 4. Runtime 契约变化

`ContainerBundle.handoff_contract` 新增两个字段：

```json
{
  "enterprise_table_policy": {
    "mode": "adapt_existing_or_create_minimal"
  },
  "skill_rule_capture_policy": {
    "mode": "ask_before_skill_update",
    "required_question": "是否更新到对应 Skill 以便下次自动复用",
    "authorization_required": true
  }
}
```

OpenClaw 版 SKILL frontmatter 统一增加：

```yaml
table_policy: adapt_existing_or_create_minimal
rule_capture: ask_before_skill_update
```

## 5. 飞书课程同步原则

1. Lesson 文案讲清“为什么这样做、课堂怎么用、企业怎么迁移”，不要把仓库里的执行契约长篇复制进去。
2. 描述词和复制词必须改掉“必须准备固定 5 张表 / 固定表结构 / 标准 Base 作为前置”的强制语气。
3. 飞书仍可作为课堂标准沙盘，但要明确它是演示容器和参考模板，不是企业唯一答案。
4. 所有主代理和子代理增强执行词都要加入两条约束：企业表格适配已有表头；确认新规则后先询问是否沉淀到对应 Skill。
5. Lesson 里如需引用执行契约，只链接 GitHub 仓库或点名文件，不在飞书端重复维护脚本细节。

## 7. 术语替换规则

| 旧口径 | 新口径 |
| --- | --- |
| 必须先准备标准 Base / 5 张表 | 飞书沙盘可用参考模板；企业落地优先沿用已有表头 |
| 固定表结构 | 标准字段映射 + 企业表头适配 |
| 所有数据稳定留存在同一套飞书表结构 | 所有数据围绕同一数据归口和主线索中心；容器可以是飞书、Excel / CSV、CRM 或企业已有系统 |
| 子代理写入指定飞书表 | 子代理输出标准化结果；如使用飞书沙盘则写入指定表，如使用企业表格则先做表头映射 |
| 规则默认沉淀 | 规则沉淀必须先询问并获得授权 |
